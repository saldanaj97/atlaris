# 1Password Environments for cloud agents

Bootstrap `.env.local` (or another agent env file) inside Codex / Cursor cloud agents from a 1Password Environment. This is **not** the Vercel Preview/Production env path — hosted deploys still use Vercel project env and the `.env.preview.example` / `.env.production.example` templates.

## Prerequisites

Configure these as **cloud agent secrets** (not committed):

| Secret | Purpose |
| ------ | ------- |
| `OP_ENVIRONMENT_ID` | 1Password Environment ID passed to `op environment read` |
| `OP_SERVICE_ACCOUNT_TOKEN` | Service account token for the `op` CLI |

The setup script unsets `OP_CONNECT_HOST` and `OP_CONNECT_TOKEN` so Connect auth cannot shadow the service account.

## Run

From the repo root (or any git worktree):

```bash
bash scripts/agents/codex-1password-env.sh
```

What the script does:

1. Installs the 1Password CLI (`op`) on Debian/Ubuntu containers when missing or when `op environment read` is unavailable.
2. Verifies service-account auth with `op user get --me`.
3. Reads the Environment and writes dotenv `KEY=value` lines to `AGENT_ENV_FILE` (default: `<repo>/.env.local`).
4. Prefixes the file with `# Generated by scripts/agents/codex-1password-env.sh from 1Password Environment` and `chmod 600`.

## Overwrite rules

| Condition | Behavior |
| --------- | -------- |
| Target file missing | Write generated file |
| Target exists and first line is the generator marker | Replace safely |
| Target exists and was **not** generated by this script | Fail unless `AGENT_ENV_OVERWRITE=1` |

```bash
AGENT_ENV_OVERWRITE=1 bash scripts/agents/codex-1password-env.sh
AGENT_ENV_FILE=/tmp/agent.env bash scripts/agents/codex-1password-env.sh
```

## Template shape

`.env.agents.example` documents a typical agent payload (local product-testing defaults, optional worker tokens, mock AI). Keep real secrets only in the 1Password Environment.

For how those variables are parsed in-app, see [Environment variables](../development/environment.md). For local product-testing vs real Clerk checkout, see the Clerk development checkout section in that doc.

## Pitfalls

- Missing `OP_ENVIRONMENT_ID` or `OP_SERVICE_ACCOUNT_TOKEN` fails fast with an explicit error.
- Non-Debian containers without `op` already installed cannot use the automatic install path.
- Do not commit generated `.env.local` or paste Environment contents into PRs/logs.
- Successful install/auth with an empty Environment payload fails validation (no `KEY=value` lines).
